# 아 맞다, 인생! — 최종 로드맵 인쇄·PDF 저장 품질 수정 프롬프트

- 작성일: 2026-11-08
- 대상 저장소: `infosys-hackathon-corrected` (Next.js App Router + TypeScript + Tailwind v4)
- 대상 화면: `03 다` 최종 로드맵 `/output` (확정 후 **"인쇄 · PDF 저장"** 버튼 → `window.print()`)
- 담당 경로: FE(`src/features/planner/**`, `src/app/globals.css`). 계산·자료(`src/engine/**`, `src/contracts/**`, `src/data/**`)는 바꾸지 않는다.

---

## 0. 너의 역할과 목표

너는 웹 인쇄 CSS(`@media print`, `@page`, 페이지 나눔)와 Safari·Chrome 인쇄 엔진 차이를 잘 아는 프런트엔드 엔지니어다.

사용자가 `/output`에서 "인쇄 · PDF 저장"을 눌러 PDF로 저장하면 다음 문제가 생긴다. 목표는 **어떤 브라우저(특히 macOS Safari)로 저장해도 깔끔한 A4 문서**가 나오게 하는 것이다.

1. **검정색으로 칠해진 영역이 생긴다.** 화면에서는 연한 배경·도장(스탬프)·빗금인데 PDF에서는 검은 덩어리로 보인다.
2. **글자 크기가 맞지 않는다.** 너무 크거나 작고, 제목·본문·표의 위계가 무너진다.
3. **배열이 깨진다.** 화면용 2열·5열 레이아웃이 A4 폭에 억지로 들어가 칸이 좁아지거나 겹친다.
4. **페이지마다 잘린다.** 학기 카드·연도 줄·표가 페이지 경계에서 반으로 잘리거나, 큰 빈 공간이 생긴다.

결과 PDF는 학생이 학기마다 꺼내 보는 **"계획 문서"** 다. 화면을 그대로 찍은 사진이 아니라, 종이용으로 다시 짠 문서처럼 보여야 한다.

## 2. 원인 후보 (반드시 재현해서 확인할 것 — 추측으로 고치지 말 것)

각 후보를 실제 인쇄 미리보기에서 켜고 끄며 확인하고, 최종 보고에 **어느 것이 실제 원인이었는지** 적는다.

| # | 후보 | 위치 | 왜 의심되나 |
|---|---|---|---|
| A | `.stamp { mix-blend-mode: multiply; }` | `globals.css` `.stamp` | WebKit(Safari)은 인쇄할 때 혼합 모드가 있는 요소를 투명도 레이어로 그리며, 배경이 투명하면 **검은 사각형**으로 떨어지는 경우가 있다. 중단 학기 카드의 "군 복무·교환학생·휴학" 도장과 확정 "확 정" 도장이 여기에 해당한다. |
| B | `* { print-color-adjust: exact; -webkit-print-color-adjust: exact; }` | `globals.css` `@media print` | **모든 요소**의 배경을 강제로 인쇄한다. `bg-ink`(거의 검정 #26241f) 같은 화면용 진한 배경이나 반투명 오버레이까지 그대로 나온다. 꼭 필요한 요소에만 `exact`를 줘야 한다. |

| D | `.ruled`(줄 노트 반복 그라디언트) | 수강 학기 카드 `ul.ruled` | 인쇄 배율에서 34px 간격이 행 높이와 어긋나 줄이 글자를 가로지르거나 진하게 뭉칠 수 있다. |

| G | 화면 레이아웃을 그대로 인쇄 | `OutputScreen`·`Roadmap` | 글자 크기가 `text-[13.5px]`·`text-[34px]`처럼 px로 박혀 있어 인쇄 배율에서 위계가 무너지고, 5열 요약·2열 학기 grid가 A4 폭(약 186mm)에서 비좁다. |
| H | 연도 줄 전체에 `break-inside: avoid` | `Roadmap.tsx` 61행 | 1·2학기 카드를 묶은 **연도 줄 전체**를 쪼개지 못하게 해서, 한 줄이 남은 공간보다 크면 통째로 다음 쪽으로 넘어가 큰 빈칸이 생긴다. 한 쪽보다 크면 결국 잘린다. Safari는 grid 안의 `break-inside`를 Chrome과 다르게 처리한다. |
| I | `min-h-dvh`, `sticky`, `overflow-hidden` | `PlannerApp.tsx`, 카드들 | 인쇄에서 `dvh` 높이나 `overflow-hidden`이 카드 아래쪽을 잘라 먹거나, 빈 페이지를 만든다. |

## 3. 권장 해결 방식

### 3.1 화면 레이아웃을 고치지 말고 **인쇄 전용 문서**를 따로 만든다(권장)

- `src/features/planner/components/PrintPlan.tsx`(새 파일)를 만든다.
  - 화면에서는 `hidden`, 인쇄에서만 `print:block`으로 보인다.
  - 기존 화면 전체(요약 칸·Roadmap·aside·채팅·버튼)는 인쇄에서 `print:hidden`으로 숨긴다.
- `PrintPlan`은 `OutputScreen`이 이미 계산한 값만 받는다: `plan`, `result`(= `simulatePlan` 결과), `guidance`, `dataset`, 교양 자리(`plan.genEd`), 군·교환 정보(`plan.military`, `plan.exchange`, `draft.exchangeChoice`), 체크 상태(`checked`).
  - **새로 계산하지 않는다.** 화면에 보이는 값과 PDF 값이 같아야 한다.
  - 교환 학기가 있는 계획은 완료 학기를 화면처럼 "교환 인정 확인 후"로 표시한다(`exchangePending` 로직 재사용).
- 이렇게 하면 화면 디자인(종이 질감, 도장, 빗금, 손글씨 폰트)을 건드리지 않고, 인쇄는 **단순한 문서 레이아웃**으로 안정적으로 만들 수 있다.

### 3.2 인쇄 문서의 디자인 규칙

**색**

- 배경은 흰색(#fff). 본문 글자는 #1a1a1a. 보조 글자는 #555. 연한 구분선은 #cfcfcf.
- 강조색은 최대 2개만 쓴다: 진로·완료 학기 강조 빨강(#b3392e), 교양 자리 파랑(#2d4a85).
- 인쇄 문서 안에서는 다음을 **쓰지 않는다**: `mix-blend-mode`, 반투명 배경(`/[0.05]` 같은 알파), 그라디언트, 그림자, `clip-path`, `transform: rotate`.
- `print-color-adjust: exact`는 `*` 전체에서 빼고, 색이 꼭 필요한 작은 요소(진로 색 점, 상태 배지 테두리)에만 준다.
- 중단 학기(군 복무·휴학·교환학생)는 빗금 대신 **연회색 단색 배경(#f2f2f2) + 굵은 글자 라벨**로 표시한다. 흑백 프린터에서도 구분돼야 한다.
- 색만으로 구분하지 않는다. 진로 색 점 옆에 항상 글자(이수구분·진로명)를 둔다.

**글자(pt 단위로 지정 — 인쇄는 px 대신 pt)**

| 요소 | 크기 | 굵기 |
|---|---|---|
| 문서 제목(트랙 이름) | 16pt | 700 |
| 부제·생성 정보 | 8.5pt | 400 |
| 섹션 제목(요약, 학기별 로드맵, 준비할 것, 확인 필요) | 11.5pt | 700 |
| 본문·표 내용 | 9pt | 400 |
| 표 머리·보조 설명 | 8pt | 400~600 |
| 최소 크기(각주 포함) | **7.5pt 미만 금지** | — |

- 글꼴은 화면과 같은 Pretendard(본문)·Gowun Batang(제목)을 쓴다. 손글씨 폰트(Nanum Pen Script)는 인쇄에 쓰지 않는다.
- 숫자 열은 `tabular-nums`로 오른쪽 정렬한다.
- 줄 간격은 본문 1.45, 표 1.3.
- 한국어 줄바꿈은 기존 `word-break: keep-all`을 유지하고, 긴 학수번호·URL만 `overflow-wrap: anywhere`.

**쪽 설정**

- `@page { size: A4 portrait; margin: 14mm 12mm 16mm; }`. 내용 폭은 약 186mm다.
- 모든 쪽 위쪽에 짧은 머리글 한 줄: "아 맞다, 인생! · {이름}님 학기 로드맵 · {확정일 또는 '확정 전 초안'}".
  - Safari는 `@page` 여백 상자(`@top-center`)를 지원하지 않는다. 그러므로 첫 쪽에 머리글을 두고, 표는 `<thead>`를 쓴다(`display: table-header-group`로 쪽마다 반복).
- 쪽 번호는 브라우저 인쇄 옵션의 머리글·바닥글에 맡긴다. CSS로 강제하지 않는다(Safari 미지원). 보고에 이 한계를 적는다.

### 3.3 인쇄 문서의 구성(위에서 아래로)

1. **머리 블록**
   - 제목: 트랙 이름(예: "소프트웨어 개발 · 육군 기술행정병 · 3학년 2학기 교환 · 후반 여유형")
   - 부제: `{학과} {교육과정} 교육과정 · {확정일 확정 | 확정 전 초안} · 생성 {오늘 날짜} · 자료 {catalogVersion}`
   - 고지 한 줄: "계획·추정 결과이며 졸업 판정이 아닙니다. 확인되지 않은 값은 '확인 필요'로 표시했어요."
2. **요약 표**: 2열 × 3행 표. 화면의 5칸 grid를 쓰지 않는다.
   - 진로 / 군 복무(입대→복학 또는 '일정 미정') / 학기당 계획 학점(페이스 방식) / 예상 계획 완료(또는 '교환 인정 확인 후', '목표학점 필요') / 남은 학점·계획 학점 / 교환학생(학교·학기, 학점 인정 미정)
3. **학기별 로드맵**
   - **카드 grid가 아니라 학기 단위 블록**으로, 학기 하나를 쪼개지 않는 단위로 쌓는다.
   - 권장 형태 1(세로 목록): `[연도·학기 | 학년·유효학기 | 상태]` 머리 줄 + 과목 표(과목명 | 이수구분 | 학점) + 합계 줄(전공 · 교양 · 미지정 · 합계 / 상한).
   - 권장 형태 2(2열): 한 줄에 1학기·2학기를 나란히 두고 `.term-block` 각각에만 `break-inside: avoid`. **연도 줄 전체에는 avoid를 주지 않는다.**
   - 둘 중 하나를 고르고 이유를 보고한다. 기본은 형태 2를 권장한다. 단, 학기 블록이 너무 길어지면(과목 8개 이상) 형태 1로 바꾼다.
   - 중단 학기: 한 줄 블록 "2029년 1학기 — 군 복무(육군 현역병)"(연회색 배경, 과목 없음).
   - 완료 학기: 블록 테두리를 빨강 1pt로 하고 "여기서 계획 완료" 텍스트 라벨을 붙인다(손글씨·도장 금지).
   - 교양 자리: 과목 행과 같은 높이의 한 줄 "교양 A — 교양 자리(실제 과목 아님) · 2학점". 범례는 표 위에 한 줄.
   - "가정"(개설 시기 가정) 표시는 과목명 뒤 `(가정)` 글자로 둔다.
   - 미배치 과목이 있으면 로드맵 끝에 "아직 못 넣은 과목" 표.
4. **준비할 것(체크리스트)**
   - 체크박스는 인쇄용 사각형(□ / ☑)으로 바꾸고, 화면에서 체크한 상태를 반영한다.
   - 각 항목은 `break-inside: avoid`.
5. **자격증 준비**: 있으면 표기. "서비스 추천이며 공식 필수 자격이 아님" 문구를 둔다.
6. **공식 자료와 사용자 가정** / **가정한 것·확인 필요**: 화면 `aside`의 `<details>`는 인쇄에서 **펼친 상태**로 보여야 한다. `<details>`를 쓰지 말고 `PrintPlan`에서 목록으로 다시 그린다.
7. **꼬리 고지**: "공식 합격·학점 인정·졸업을 보장하지 않습니다. 과목 정보: 학과 교육과정표(S1). 진로·트랙 분류와 추천은 서비스 기준입니다."

### 3.4 페이지 나눔 규칙

```css
@media print {
  .print-section { break-inside: auto; }
  .print-section > h2 { break-after: avoid; }       /* 제목만 쪽 끝에 남지 않게 */
  .term-block, .check-item, .summary-table { break-inside: avoid; }
  table { break-inside: auto; }
  thead { display: table-header-group; }            /* 표 머리 쪽마다 반복 */
  tr { break-inside: avoid; }
  p, li { orphans: 2; widows: 2; }
}
```

- `break-inside: avoid`는 **한 쪽보다 작다고 확실한 블록**에만 준다. 연도 묶음·섹션 전체에는 주지 않는다.
- grid·flex 안의 아이템에 걸린 `break-inside`는 Safari에서 무시될 수 있다. 학기 블록 묶음은 grid 대신 다음 중 하나로 만든다.
  - `display: block` + `inline-block` 두 칸(폭 49%, `vertical-align: top`)
  - `display: table` 2열
- `overflow: hidden`, `min-height: 100dvh`, `position: sticky/fixed`는 인쇄 트리에서 모두 해제한다(`overflow: visible`, `min-height: 0`, `position: static`).
- 24개 학기(최대 계획)도 잘림 없이 이어져야 한다.

### 3.5 인쇄에서 반드시 숨길 것

탭 `nav`, 제본 `.binding`, 화면 머리글·꼬리글(인쇄용 꼬리 고지는 따로), `ActionBar`(아 맞다!·채팅 버튼), `FeedbackChat`, "방금 고친 것" 되돌리기 줄, 교양 추가·삭제 버튼과 상한 안내, 화면용 범례·요약 grid·`Roadmap`·`aside`(인쇄 전용 문서로 대체), 툴팁, 스크롤바, Next.js 개발 표시(`nextjs-portal`).

## 4. 하지 말 것

- 화면 디자인(종이 질감, 도장, 빗금, 손글씨, 탭 색)을 인쇄 문제 때문에 바꾸지 않는다. 인쇄에서만 다르게 그린다.
- 계산·자료를 PDF용으로 다시 계산하지 않는다. 숫자·학기·완료 시점은 화면 값 그대로 쓴다.
- 확인되지 않은 수치(졸업학점, 복무기간, 모집일)를 PDF에서 채워 넣지 않는다. 화면처럼 '확인 필요'로 둔다.
- `html2canvas`·`jsPDF` 같은 PDF 생성 라이브러리나 서버 렌더링을 추가하지 않는다. 브라우저 인쇄(`window.print()`)를 그대로 쓴다. 새 의존성은 금지다.
- `* { print-color-adjust: exact }`처럼 전체에 거는 규칙으로 해결하지 않는다.
- `zoom`·`transform: scale()`로 화면을 줄여 끼워 맞추지 않는다(글자가 흐려지고 Safari에서 잘린다).

## 5. 확인 방법(직접 해 보고 보고할 것)

### 5.1 재현과 비교

1. `npm run dev` → `/`에서 "테스트 정보로 시작하기"로 프로필 A·B·C·D를 각각 불러온다.
2. `/match`에서 1순위 트랙 "이 트랙으로 계획하기" → `/output`.
3. 교양 자리를 몇 개 넣고, 준비할 것 몇 개를 체크한 뒤 "아 맞다!"로 확정 → "인쇄 · PDF 저장".
4. 고치기 **전** PDF와 고친 **후** PDF를 같은 조건으로 저장해 비교한다.

### 5.2 브라우저·옵션 조합(모두 확인)

| 브라우저 | 용지 | 배경 그래픽 옵션 | 확인 |
|---|---|---|---|
| macOS Safari(최신) | A4 세로 | 켬 / 끔 | 검은 영역 없음, 잘림 없음 |
| Chrome(최신) | A4 세로 | 켬 / 끔 | 동일 |
| Chrome | Letter | 켬 | 폭이 달라도 잘림 없음 |

- Chrome은 개발자도구 → Rendering → "Emulate CSS media type: print"로도 미리 볼 수 있다. 최종 확인은 실제 인쇄 미리보기로 한다.
- 자동 확인(선택): 이미 있는 도구로만 한다. 새 의존성 금지. 예: Chrome headless의 `--print-to-pdf`로 PDF를 저장한 뒤 쪽수를 세어 본다.

### 5.3 내용 시나리오

- 짧은 계획(4학기), 긴 계획(10학기 이상), 최대(24학기에 가깝게: 목표학점 크게 + 학기당 학점 작게)
- 군 복무 중단이 있는 계획(프로필 A), 교환 학기가 있는 계획(프로필 B에서 교환 전략 선택)
- 교양 자리가 여러 개인 학기, 미배치 과목이 있는 계획, 목표학점 미입력 계획
- 긴 트랙 이름·긴 과목명(예: "커리어개발Ⅱ:취.창업진로포트폴리오")

## 6. 완료 기준(모두 충족)

- [ ] Safari·Chrome 어느 쪽으로 저장해도 **검게 칠해진 영역이 하나도 없다**(배경 그래픽 켬·끔 모두).
- [ ] 문서 제목 16pt, 섹션 11.5pt, 본문·표 9pt, 최소 7.5pt 이상. 손글씨 폰트를 쓰지 않는다.
- [ ] 학기 블록·체크 항목·요약 표가 **쪽 경계에서 반으로 잘리지 않는다**. 섹션 제목만 쪽 끝에 홀로 남지 않는다.
- [ ] 한 연도 묶음 때문에 반 쪽 이상 비는 공간이 생기지 않는다.
- [ ] 표 머리가 다음 쪽에서 반복된다(Chrome 기준. Safari 동작은 보고).
- [ ] 버튼·채팅·탭·제본·툴팁·교양 추가 버튼이 PDF에 나오지 않는다.
- [ ] PDF의 숫자(학기별 학점, 합계, 완료 학기, 남은 학점)가 화면과 같다. 교환 계획은 "교환 인정 확인 후"가 그대로 나온다.
- [ ] 흑백으로 인쇄해도 중단 학기·완료 학기·교양 자리가 글자로 구분된다.
- [ ] 화면(`/output`) 모양은 바뀌지 않았다(인쇄 전후 스크린샷 비교).
- [ ] `npm run check && npm run build` 통과.

## 7. 작업 방식과 보고

- 최신 `main`에서 `feat/fe-<번호>-print-pdf` 브랜치로 시작한다. 커밋은 FE 단위로 나눈다.
  - 예: ① 인쇄 전역 CSS 정리 ② `PrintPlan` 추가 ③ 화면 요소 인쇄 숨김
- 최종 보고에 포함할 것:
  1. 실제 원인(2장 후보 중 무엇이었는지, 재현 방법)
  2. 바꾼 파일과 이유
  3. 브라우저·옵션 조합별 확인 결과(5.2 표 채우기)
  4. 고치기 전·후 PDF 쪽수와 문제 구간 비교
  5. 남은 한계(예: Safari 쪽 번호·표 머리 반복 미지원)
- 실제 사용자 성적·이름이 든 PDF를 저장소에 커밋하지 않는다. 확인용 PDF는 테스트 프로필(가상 데이터)로만 만든다.
