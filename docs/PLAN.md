# 아 맞다, 인생! — 해커톤 기획서

- 기준일: 2026-11-07
- 목적: 완성 제품이 아니라 **실현 가능성 시연**. 한 사람의 입력으로 실제 계산된 계획 후보를 만들고, 고르고, 고쳐서 확정하는 흐름이 끝까지 동작하면 된다.
- 실행 계획과 담당: [TEAM.md](../TEAM.md)

## 1. 서비스 한 줄

내 이수 현황·희망 일정·우선순위를 넣으면 대학생활 계획 후보를 계산해 비교해 주고, 고른 계획을 학기별 로드맵으로 확정해 주는 서비스. 대상은 **서울캠퍼스 정보시스템학과, PC 브라우저**.

“아 맞다” = **아**름다운 인생을 **맞**춰 줍니**다**.

| 단계 | 이름 | 하는 일 |
|---|---|---|
| 아 | 내 정보 | 질문형 입력(이수 현황·끌리는 것·군대·교환학생·목표). 군대·교환학생 정보 페이지 연결 |
| 맞 | 맞춰가기 | 진로 × 입대 시기 × 교환학생 조합의 **트랙**을 추천 순위로 나열 → 트랙 정보 확인 → 기본 트랙으로 결정 |
| 다 | 다했다 | 기본 트랙 로드맵 → 피드백 채팅으로 개인 맞춤(시연용 정해진 응답, 별도 구현) → “아 맞다!” 최종 확정·PDF |

## 2. 시연 시나리오 (이것이 완료 기준)

1. 성적표 붙여넣기 또는 과목 선택으로 이수 현황 입력, 군 입대 예정·학점 페이스·우선순위 입력
2. 엔진이 계산한 후보 **최대 3개**를 카드로 비교 (추천 이유 = 실제 비교 지표)
3. 후보 하나 선택 → 입대 시점 또는 학점 페이스 수정 → 수정 전후 차이 표시
4. “맞다!”로 확정 → 학기별 로드맵·준비사항 → PDF

입력을 바꾸면 후보와 로드맵이 실제로 바뀌어야 한다. AI 키·카카오·운영 DB 없이 동작해야 한다.

## 4. 입력

| 입력 | 기준 |
|---|---|
| 시작 학기 | 로드맵을 배치할 첫 학기 |
| 이수 과목·총/전공 이수학점 | 성적표 인식 후 사용자가 확인. 전공학점은 총학점에 포함(더하지 않음) |
| 목표 총학점 | 선택. 없으면 완료 학기는 “확인 필요”로 표시 |
| 관심 진로 | 직접 고르지 않는다. 관심사 질문 답 → 6개 진로(소프트웨어 개발, 데이터·AI, 정보보안, IT 컨설팅·기획, IT 비즈니스·서비스, 금융 IT·핀테크) 중 추천 → 맞춰가기에서 선택 |
| 학점 페이스 | 학기당 상한. 사용자 제약이며 학교 승인값이 아님 |
| 군 복무 | 해당 없음 / 입영일 확정(날짜) / 시기 추천받기. 복무 기간(개월)은 사용자가 고른 계획용 가정. 추천 시 학년을 마친 직후 시점 최대 3개를 엔진이 펼쳐 비교 |
| 우선순위 | 빠른 완료 / 진로 과목 먼저 / 여유 있는 학기 중 1순위 선택 |

음수, 전공학점 > 총학점, 종료일 ≤ 시작일은 입력 오류로 표시한다. 미입력과 0은 구분한다.

## 5. 계산 규칙

- 계산은 `src/engine`의 순수 함수(`simulatePlan`, `diffPlans`)가 하고, 화면은 결과만 표시한다.
- 날짜는 `YYYY-MM-DD` 문자열 비교, 학기는 1학기 3~6월·2학기 9~12월을 **계획용 가정**으로 표시한다.
- 중단 기간과 겹치는 학기에는 과목을 배치하지 않는다.
- 진로 추천 과목을 권장 학년 순서로 학기 상한 안에서 배치한다. 권장 순서를 공식 선수조건으로 표현하지 않는다.
- 최대 24개 미래 학기까지 배치하고, 넘으면 미배치 과목과 이유를 보여준다.
- 결과 명칭은 **예상 계획 완료 학기**다. 공식 졸업 판정이 아니다.

### 5.1 후보 생성과 정렬

- 후보 = 선택한 진로 × 병역 시점(시기 추천일 때만, 최대 3) × 학점 페이스(15·18·20, 서비스 설정) 조합을 각각 `simulatePlan`으로 계산한 결과. 사용자가 고정한 값은 바꾸지 않는다.
- 결과가 같은 후보는 하나로 합친다. 후보가 1~2개면 그 수만 보여주고 가짜 후보를 채우지 않는다.
- 정렬은 사용자가 고른 1순위 지표로 한다. 같으면 정해진 순서(빠른 완료 → 진로 과목 → 여유)로 비교하고, 끝까지 같으면 고정 ID 순서.

| 우선순위 | 지표 |
|---|---|
| 빠른 완료 | 예상 계획 완료 학기 (목표학점이 없으면 이 지표는 비교에서 제외하고 이유 표시) |
| 진로 과목 먼저 | 진로 핵심 과목의 평균 배치 학기 |
| 여유 있는 학기 | 학기 최대 계획학점 |

- 카드의 추천 이유는 실제 비교 지표 값으로 만든다.

## 6. 맞: 수정·비교·확정

- 지원하는 수정: 입대 시점(중단 기간 이동), 학점 페이스, 진로.
- 수정하면 다시 계산하고 **수정 전 vs 수정 후**를 `diffPlans`로 비교해 보여준다(과목 이동, 학기별 학점, 완료 학기 차이).
- “맞다!”로 확정하면 다 단계로 이동. “다시 맞추기”로 돌아갈 수 있다.
- 저장은 브라우저 localStorage(입력·확정 계획·체크 상태). 새로고침 후 복구된다.

## 7. 다: 로드맵과 준비사항

- 학기별 로드맵: 수강/중단 구분, 과목·이수구분·학점, 미배치 과목.
- 준비사항: `buildGuidance`가 결과에서 만든다(복학 전 교육과정 재확인, 진로 핵심 과목 준비 등). 확인되지 않은 날짜는 만들지 않고 “신청 기간 확인 필요”로 표시.
- 체크 상태 저장, 인쇄·PDF.

## 8. 구현 경계

- 화면은 `getCatalog()`로만 자료를 받는다. DB SDK·외부 사이트를 직접 호출하지 않는다.
- 자료는 검토한 JSON fixture(`CATALOG_SOURCE=fixture`)로 시연한다.
- 입력과 무관하게 미리 정한 후보·로드맵을 보여주지 않는다(결과 하드코딩 금지).

## 9. 이번에 하지 않는 것

교환학생 인정학점 계산, 버전 이력 관리(직전↔현재 비교만), AI 문장 해석, 과목 우선배치, 카카오 알림·로그인, 캘린더, 다전공, Supabase 운영 전환, 다른 학과. 필요하면 발표에서 “확장 가능성”으로 한 줄만 언급한다.

BE-1 v2 계약(`src/contracts/types.ts`)에는 이런 확장용 필드도 이미 있다. 계약은 유지하되 이번 구현은 위 범위만 채우고, 나머지 필드는 `null`/미사용으로 둔다.

## 10. 교환학생 계획 v1 범위 (2026-11-08 합의)

명세: `ah-matda-exchange-student-planner-prompt.md`. 이번 버전은 아래만 만든다.

| 구분 | 이번에 함 | 이번에 하지 않음 |
|---|---|---|
| 입력 | 한 화면 한 질문: 관심 정도 → 시기 → 기간 → 중요한 것(최대 2) → 어학 상태 → 예산·주거. 기존 학업·군 입력은 다시 묻지 않음 | 여권·국적 서류, 영역별 점수는 해당 학교가 상위 후보일 때만(이번엔 안내만) |
| 자격 | 한양대 공통 자격과 파견교 자격을 따로 `pass/fail/unknown` 판정(회차별 규칙) | 합격 가능성·경쟁률·TO 기반 확률 |
| 학교 | 2027-1 본모집 파견교 엑셀(서울)에서 조사 후보 20개교를 셀 근거와 함께 옮김. 2027-1은 마감된 회차라 이후 학기에는 **이전 회차 자료(stale)** 로만 표시 | 최신 회차 확정 추천, QS 순위 반영, 실시간 비용·환율 |
| 과목 | 엑셀의 수강불가 학과·참고 링크로 학과 접근 `limited/unknown`만 판정. "제한 목록에 없음"을 수강 가능으로 보지 않음 | 현지 과목 목록·선수과목·정원 판정 |
| 학점 인정 | **미정(unknown) 유지.** 교환 학기에 국내 과목 미배치, 완료 학기 확정 안 함. 한양대 공식 환산 규칙은 안내로만 | 인정학점 계산, 전공·교양 구분 |
| 결과 | 1순위 + 위험을 나눈 백업 최대 2 + 지원~귀국 준비 로드맵, 선발·파견교·과목·학점 인정 분기 | 백업을 실제 지원 지망 순서로 확정 |
| 로드맵 연결 | 선택한 교환 학기를 트랙 계산에 넘기고, 인정 미정이면 최종 화면에서도 완료 시점을 "교환 인정 확인 후"로 표시(v1 재계산 값으로 확정하지 않음) | v2 결과 전체를 최종 로드맵이 직접 소비하는 구조 개편(후속) |
| 군 복무 | 군 전략 분기별로 교환 학기와 겹침을 hard/conditional로 구분 표시 | 고정 일정 자동 이동 |

- 학교 추천은 **공식 자료 기반이지만 지난 회차(2027-1) 기준**이다. 다음 회차(2027-2) 공고·엑셀이 나오면 fixture를 새 회차로 추가한다(이전 offering을 복제하지 않는다).
- 과거 공고만 있을 때: 날짜는 "공고 확인 필요", 학교는 "2027-1 자료 기준 · 다음 공고에서 재확인" 배지로 보여 준다.
