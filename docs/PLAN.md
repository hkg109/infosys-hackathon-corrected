# 아 맞다, 인생! — 서비스 기획서 v2

> "아 맞다! 그거 신청 기간이었지…"를 없애는 대학생활 설계 서비스.
> 내 정보를 넣으면 여러 대학생활 트랙을 순위대로 보여주고, 하나를 골라 피드백으로 다듬은 뒤, 확정한 트랙에 필요한 신청 기간을 카카오톡으로 먼저 알려준다.

---

## 1. 핵심 흐름: 아 · 맞 · 다

```
[아] 아 맞다      →   [맞] 맞춰가기                         →   [다] 다 했다
내 정보 입력          트랙 선택 화면(순위 카드)                    최종 4년+ 로드맵
                      → 트랙 하나 선택 = 기본 트랙                 + 할 일 타임라인
                      → 피드백으로 개인 맞춤(여러 번)              + 카카오톡 알림 신청
                      → "맞다!" 버튼으로 확정
```

| 단계 | 이름 | 사용자가 하는 일 | 결과 |
|---|---|---|---|
| 아 | 아 맞다 | 내 정보 입력(모르는 항목은 비워도 됨) | 계획 입력값 |
| 맞 | 맞춰가기 | 트랙 카드 비교 → 하나 선택 → 피드백 반복 → "맞다!" | 확정된 내 트랙 |
| 다 | 다 했다 | 최종 로드맵 확인, PDF 저장, 알림 신청 | 4년+ 로드맵, 할 일과 알림 |

---

## 2. 아 단계: 내 정보 입력

### 입력 항목
- **기본:** 이름(선택), 입학연도, 학과, 관심 진로(여러 개 선택 가능, 모르면 비워두기)
- **지금까지:** 마친 학기, 총 이수학점과 전공학점, 이수 과목(성적표 붙여넣기 또는 직접 체크)
- **병역:** 마침 / 앞으로 예정 / 해당 없음
  - 예정이면 입대 시점(학년·연도·학기)
- **교환학생:** 관심 있음 / 없음
  - 있으면 희망 시점
- **휴학:** 계획 있음 / 없음
  - 있으면 시점
- **우선순위(트랙 순위에 사용):** 빠른 졸업 / 진로 준비 / 여유 있는 학기 / 교환·대외 경험 중 중요한 순서

### 원칙
- **학년·연도·학기는 선택 입력이다.** 비우면 맞 단계에서 가능한 시점 후보를 자동으로 만들어 트랙 카드로 보여준다.
- **성별 대신 병역 상태를 직접 묻는다.**
  - 성별은 군 복무 판단에만 필요한데, 면제자·복무 완료자·외국인 학생은 성별로 갈리지 않는다.
  - 성별은 민감 정보이므로 받지 않는 것이 안전하다.
  - (초안의 "남성 → 군필/미필, 여성 → 교환·휴학" 분기는 "병역 질문 + 교환·휴학 질문"으로 합친다.)
- **입력값은 기본적으로 이 브라우저에만 저장한다.** 카카오톡 알림을 신청한 경우에만 알림에 필요한 최소 정보를 서버에 저장한다(6장).

## 3. 맞 단계: 트랙 선택 화면과 맞춤화

### 3.1 트랙이란
트랙 = **진로 × 병역 시점 × 교환·휴학 시점 × 학기당 학점 페이스(× 다전공 여부)**의 조합.
예) "2학년 마치고 입대 · 정보보안 집중 · 3학년 2학기 교환"

### 3.2 트랙 후보 만들기 (하드코딩 없음)
1. 사용자가 비워 둔 항목의 가능한 값을 규칙으로 펼친다.
   - 예: 입대 시점 = 1학년 후 / 2학년 후 / 3학년 후
2. 각 조합마다 계획 엔진(`simulatePlan`)으로 실제 학기 배치와 예상 졸업 학기를 계산한다.
3. 계산이 불가능하거나 입력 규칙에 어긋나는 조합은 버린다.

### 3.3 순위 매기기
- 사용자가 고른 우선순위에 따라 **공개된 점수식**으로 순위를 매긴다.
  - 예: 빠른 졸업 = 예상 졸업 학기, 진로 준비 = 진로 핵심 과목을 얼마나 일찍 듣는지, 여유 = 학기당 평균 학점
- 점수와 근거를 카드에 같이 보여준다. AI가 순위를 정하지 않는다(결과를 재현하고 설명할 수 있어야 함).

### 3.4 트랙 선택 화면 (게임 캐릭터 선택 화면 같은 카드형 UI)
- 화면 가득 트랙 카드가 **순위대로** 나열된다(1위 강조, 상위 3~5개 + "더 보기").
- **카드 앞면:** 순위, 트랙 이름, 대표 태그(빠른 졸업·교환 포함 등), 예상 졸업 학기, 핵심 과목 2~3개
- **카드 클릭 → 상세 패널:**
  - 대략적인 로드맵(학기 미니 타임라인)
  - 장점, 특징, 주의할 점(3줄 이내)
  - 이 트랙에 필요한 신청 일정 목록(입영 신청, 교환학생 지원 등, 출처 포함)
  - "이 트랙으로 시작" 버튼
- 디자인은 특정 게임의 화면이나 브랜드를 따라 하지 않고, 우리 서비스의 고유한 카드 선택 화면으로 만든다.

### 3.5 기본 트랙 → 피드백 → 확정
1. 선택한 트랙이 **기본 트랙(v1)**이 된다.
2. **피드백 방법 두 가지:**
   - 버튼형: "입대를 한 학기 늦추기", "이 과목 먼저", "학기당 학점 줄이기" 등
   - 자유 문장: "3학년 때 교환학생 가고 싶어" → AI가 계획 입력 변경으로 해석(7장)
3. 피드백할 때마다 새 버전(v2, v3 …)이 쌓인다. 아무 버전끼리 나란히 비교할 수 있다(기존 플랜 비교 기능 확장).
4. **"맞다!" 버튼**으로 마음에 드는 버전을 확정하면 다 단계로 넘어간다. 다 단계에서 "다시 맞추기"로 돌아올 수 있다.

## 4. 다 단계: 최종 로드맵

| 출력 | 내용 | 필요한 자료 | 출처 표시 |
|---|---|---|---|
| 학년별 과목 | 학기별 배치 + 이수구분(전공기초·전공핵심·전공심화·교양필수) | 학과 교육과정표, 대학 교양 규정 | 학교 공식 |
| 선수강 | 공식 선수요건과 권장 순서를 구분해 표시 | 공식 선수요건 / 선배·서비스 추천 | 공식 / 추천 구분 |
| 자격증 | 진로별 추천 자격증과 준비 시기 | 진로별 자격증 후보 목록, 시험 일정 | 서비스 추천 + 시행기관 공식 일정 |
| 군 입대 준비 | 입영 신청 등 할 일과 시기 | 병무청 공지 | 기관 공식 |
| 교환학생 준비 | 어학 성적, 지원 시기, 학점 인정 확인 | 학교 국제처 공지 | 학교 공식 |
| 다전공·복수전공 | 진로에 맞는 후보와 이유, 신청 요건 | 학교 다전공 규정 | 이유는 추천, 요건은 공식 |
| 할 일 타임라인 | 위 항목을 날짜순으로 모은 목록 | 위 자료 | 항목별 |
| PDF 저장 | 최종 로드맵 인쇄 | — | — |

**원칙:** 공식 자료로 확인하지 못한 수치(졸업학점, 선수요건, 신청 기간, 시험일, 신청 요건)는 만들지 않는다. 대신 "확인 필요"와 공식 공지 링크를 보여준다.

## 5. 자료 출처 3종과 하드코딩 금지

| 출처 | 예 | 화면 표시 | 검토 |
|---|---|---|---|
| 학교·기관 공식 | 과목, 이수구분, 선수요건, 신청 기간 | "공식" + 원문 링크 + 확인일 | 수집 → 검토 → 게시 |
| 선배 추천 | 과목 수강 팁, 권장 순서, 자격증 후기 | "선배 추천" + 학번 | 작성 → 검토 → 게시 |
| AI 추천 | 트랙 설명, 피드백 해석, 추천 이유 | "AI 추천" | 서버에서 형식·과목 코드 검사 |

### 지금 코드에서 자료로 옮겨야 할 것
- **진로 목록:** 지금 "정보보안 / 데이터 분석"이 코드에 고정돼 있다. 학과 자료에서 받아야 다른 학과로 확장할 수 있다.
- **준비사항 문구:** 지금 `buildGuidance` 안에 문장으로 고정돼 있다. 준비 항목 템플릿을 DB로 옮기고 출처를 붙인다.
- **학기 기간:** 지금 "1학기 3~6월, 2학기 9~12월" 가정이 엔진에 있다. 학사일정 자료로 바꾼다.
- **트랙 후보 규칙과 점수식:** 코드가 아니라 설정 자료로 두어, 학과별로 조정할 수 있게 한다.

### 선배 추천 시스템 (확장)
- 선배가 과목·진로·학년별 팁을 쓰고, 검토를 거쳐 게시한다.
- 작성자 확인(학교 메일 인증 등), 신고 기능, 공개 범위(DB 접근 정책)가 필요하다.
- 해커톤에서는 팀원이 직접 쓴 추천 몇 개를 "선배 추천(팀원 작성)"으로 표시해 넣고, 작성 화면은 이후에 만든다.

## 6. 카카오톡 알림: "아 맞다!"를 없애는 기능

### 6.1 무엇을 보내나
확정한 트랙에 필요한 신청 일정만 보낸다.
- 예: 입영 신청 기간 시작, 교환학생 지원 마감 2주 전, 자격증 접수 시작, 다전공 신청 기간
- 메시지마다 공식 공지 링크를 넣는다.
- 일정이 아직 공지되지 않았으면 날짜를 추측하지 않는다. 대신 "작년 이맘때 공지가 올라왔어요. 이번 공지를 확인하세요"처럼 **공지 확인 알림**을 보낸다(작년 일정도 출처가 있을 때만).

### 6.2 발송 방법 비교

| 방법 | 내용 | 조건 | 해커톤 적합도 |
|---|---|---|---|
| 카카오톡 "나에게 보내기" | 사용자가 카카오 로그인으로 동의하면 본인 카톡(나와의 채팅)으로 메시지 발송 | 카카오 개발자 앱 등록, 메시지 전송 동의 항목 설정(세부 조건은 카카오 개발자 문서로 확인 필요) | **시연용으로 적합** |
| 카카오 알림톡 | 카카오톡 채널 이름으로 정보성 메시지 발송 | 카카오톡 채널, 사업자 등록, 발송 대행사 계약, 메시지 템플릿 사전 검수 | 정식 서비스용, 해커톤 기간에는 어려움 |
| 캘린더 파일(.ics) 내보내기 | 일정을 구글·애플 캘린더에 한 번에 추가 | 서버 저장 없이 가능 | 카톡을 못 쓸 때의 대안 |

### 6.3 필요한 서버 기능 (지금은 서버에 개인 정보가 없다)
- 알림 신청 시 **명시적 동의**를 받고, 알림에 필요한 최소 정보만 저장한다: 확정 트랙의 일정 목록, 카카오 사용자 식별자, 토큰. 이름과 성적표는 저장하지 않는다.
- 토큰은 서버에서만 보관하고, 만료와 갱신을 관리한다.
- 예약 발송: 매일 정해진 시간에 오늘 보낼 알림을 찾아 발송한다(Vercel Cron 등).
- 알림 끄기와 데이터 삭제 버튼을 둔다.

### 6.4 일정 자료 파이프라인
1. 병무청, 학교 국제처, 자격 시행기관 공지를 수집한다.
2. 날짜를 뽑는다. AI가 공지 문장에서 날짜를 뽑게 할 수 있지만, 사람이 검토한 뒤 게시한다.
3. 게시된 일정만 알림 대상이 된다(기존 "수집 → 검토 → 게시" 구조 재사용).

## 7. AI 활용 범위

### 쓰는 곳
1. **피드백 해석:** 자유 문장을 계획 입력 변경(정해진 JSON 형식)으로 바꾼다. 계산은 엔진이 다시 한다.
2. **트랙 설명:** 엔진 결과를 받아 카드의 장점, 특징, 주의할 점을 쓴다.
3. **추천 고르기:** DB에 있는 자격증, 다전공, 선배 추천 후보 중에서 고르고 이유를 쓴다. 후보 밖의 항목은 만들지 않는다.
4. **공지 날짜 추출 보조:** 사람의 검토를 거친 뒤에만 게시한다.

### 쓰지 않는 곳
- 학점 계산, 학기 배치, 졸업 학기 추정, 트랙 순위(엔진과 점수식이 함)
- 졸업학점, 선수요건, 신청 기간, 시험일을 지어내는 일

### 안전장치
- AI 호출은 서버 라우트에서만 하고, API 키는 서버 환경 변수에만 둔다.
- 응답 형식을 검사하고, 과목 코드가 실제 자료에 있는지 확인한다. 통과하지 못하면 버린다.
- 이름, 성적표 원문 같은 개인 정보는 보내지 않는다.
- AI가 실패해도 트랙 후보, 순위, 로드맵은 엔진만으로 동작한다.

| API `src/app/api` | `GET /api/catalog` | `POST /api/assist`(AI), 알림 신청·해지, 카카오 로그인 콜백, 예약 발송 |
| DB `supabase` | 과목, 진로 태그, 학사 규칙, 출처, 자료 버전 | 이수구분, 자격증, 신청 일정, 준비 항목 템플릿, 선배 추천, 알림 구독 |

## 9. 해커톤 범위

| 기능 | 시연 전 (필수) | 시연 후 (확장) |
|---|---|---|
| 아: 입력 | 병역·교환·휴학·우선순위 입력, 시점은 선택 입력 | 학과 선택(다른 학과) |
| 맞: 트랙 선택 화면 | 엔진으로 후보 생성, 점수 순위, 카드와 상세 패널 | 다전공 조합 |
| 맞: 피드백 | 버튼형 피드백, 버전 비교, "맞다!" 확정, 자유 문장 해석 1종(AI) | 대화형 조정 |
| 다: 로드맵 | 학년별 과목(이수구분은 모은 만큼), 진로별 자격증 후보와 공식 링크, 준비 항목, PDF | 다전공 추천, 시험 일정 연동 |
| 알림 | 카카오톡 "나에게 보내기"로 알림 1건 시연, 또는 캘린더 파일 내보내기 | 알림톡, 예약 발송 운영 |
| 선배 추천 | 팀원 작성 추천 몇 개(표시 구분) | 작성·검토·인증 기능 |

## 10. 역할 분담 (경로 기준 유지)

- **정예준 (계약·엔진·API)**
  - 계약 타입 추가(트랙, 버전, 교환학생, 추천, 알림 일정)
  - 트랙 후보 생성과 점수식
  - `POST /api/assist`(AI 입출력 형식과 검사)
  - 카카오 로그인과 메시지 발송 서버 라우트
- **정재헌 (DB·자료)**
  - 이수구분 채우기
  - 자격증, 신청 일정, 준비 항목, 선배 추천 테이블과 기초 자료(출처 포함)
  - 알림 구독 테이블과 접근 정책
- **한지석 (화면)**
  - 아·맞·다 3단계 화면, 트랙 선택 카드와 상세 패널
  - 피드백 버튼과 버전 비교, "맞다!" 확정
  - 최종 로드맵, 알림 신청 화면

## 11. 결정 필요

1. **해커톤 범위:** 9장 "시연 전" 범위로 갈지
2. **입력:** 성별 대신 병역 상태를 직접 묻는 것에 동의하는지
3. **알림 방식:** 카카오 "나에게 보내기"로 시연할지, 캘린더 파일로 대신할지. 카카오면 누구 계정으로 개발자 앱을 만들지
4. **AI:** 어떤 제공자의 키를 쓸지(서버 환경 변수로만 보관)
5. **자료:** 시연 전에 모을 범위(이수구분, 자격증 후보, 입영·교환학생 신청 공지)

## 12. 위험 요소

| 위험 | 내용 | 대응 |
|---|---|---|
| 자료 부족 | 일정·요건 자료가 없으면 알림과 추천이 비어 보인다 | 자료 수집을 가장 먼저 시작하고, 없는 항목은 "공지 확인" 알림과 링크로 대신한다 |
| 잘못된 정보 | AI나 추측으로 날짜·요건을 만들면 서비스 신뢰가 무너진다 | 출처 3종 표시, 공식 일정만 알림, 사람 검토 후 게시 |
| 개인 정보 | 알림 때문에 처음으로 서버에 개인 정보가 저장된다 | 명시적 동의, 최소 저장, 해지·삭제 기능 |
| 카카오 연동 시간 | 앱 등록, 동의 항목 설정, 로그인 구현에 시간이 든다 | 시연은 "나에게 보내기" 1건, 대안으로 캘린더 파일 준비 |
| 범위 과다 | 해커톤 기간에 전부 만들기 어렵다 | 9장 "시연 전"만 우선 |
