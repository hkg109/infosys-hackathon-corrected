## 1. 서비스와 이번 MVP

내 정보와 우선순위를 바탕으로 대학생활 계획 후보를 계산하고, 비교·수정하여 내 로드맵을 확정하는 서비스다. 장기적으로는 확정한 계획에 필요한 신청 시기를 먼저 알려준다.

이번 MVP는 **서울캠퍼스 정보시스템학과, PC 브라우저**를 대상으로 한다.

| 단계 | 이름 | 핵심 행동 | 결과 |
|---|---|---|---|
| 아 | 아 맞다 | 내 정보·이수 현황·희망 일정·우선순위 입력 | 계산에 사용할 입력과 미확인 항목 |
| 맞 | 맞춰가기 | 후보 비교 → 선택 → 조건 수정 → 버전 비교 → “맞다!” | 사용자가 확정한 계획 버전 |
| 다 | 다 했다 | 학기별 로드맵·준비사항 확인, 체크, PDF 저장 | 다시 수정할 수 있는 계획과 할 일 |

**기본 시연:** 입력 → 실제 계산한 후보 최대 3개 비교 → 하나 선택 → 입대 시점 또는 학점 페이스 수정 → 전후 비교 → 확정 → PDF.

카카오톡 알림, 예약 발송, 알림 구독 DB, 카카오 로그인, 캘린더 내보내기는 **발표에서 설명할 향후 확장**이다. 이번 필수 구현과 완료 기준에 넣지 않는다.

### 2.3 아직 확정할 수 없는 항목

- 개인별 졸업 총학점·전공학점·교양학점·필수과목 목록과 그 적용 교육과정.
- 과목별 공식 선수관계, 미래 학기의 실제 개설, 수업 시간·정원·폐강 여부.
- 군별 복무기간, 입영 가능 여부, 실제 전역일·복학 승인 조건.
- 교환학생의 지원 자격·기간, 상대교 과목, 국내 학점·학기 인정.
- 다전공의 자격·선발·중복학점 인정, 자격증별 응시 자격·시험 일정.
- 미래 입영·교환·복학·다전공 신청 마감일.

위 항목은 `unknown`으로 유지하거나 사용자가 확인한 값/명시한 가정으로 입력한다. S2의 2026-2 수강신청 날짜를 미래 학기의 신청일로 재사용하지 않는다.

| 교환학생 | 군 복무·휴학과 다른 학기 상태로 모델링. 인정값이 미정이면 0학점으로 확정하지 않음 | 권장안 채택 |
| 트랙 순위 | MVP는 공개된 지표를 **사용자 우선순위 순서대로 비교**. 가중 총점은 후속 기능 | 권장안 채택 |
| 피드백 | 기본은 입대 시점·학점 페이스 등 입력 변경. 과목 우선배치는 별도 엔진 확장 후 제공 | MVP 결정 |
| 자료 제공 | 먼저 검토한 fixture로 전체 흐름 완성. DB 게시본 전환은 별도 카드 | 권장안 채택 |
| AI | 핵심 계산은 API 키 없이 동작. 자유 문장 해석은 기본 기능 완료 후 선택 작업 | 범위 권장안 |

## 4. 아: 입력과 검증

### 4.1 입력 계약

| 입력 | 처리 기준 |
|---|---|
| 이름 | 선택. 화면 표시용이며 계산·AI 요청에서 제외 |
| 학과·캠퍼스 | MVP는 서울 정보시스템학과로 고정 표시 |
| 입학연도·적용 교육과정 | 서로 다른 값. 입학연도만으로 개인 적용 교육과정을 확정하지 않음 |
| 계획 시작 학기 | 실제 배치의 기준. 사용자가 선택하며, 없으면 학기 없는 추천·확인사항까지만 제공 |
| 완료 학기·총/전공 이수학점 | 0과 미입력 구분. 전공학점은 총학점에 포함하며 별도 합산하지 않음 |
| 이수 과목 | 성적표 붙여넣기 또는 직접 선택. 인식 결과를 확인한 뒤 반영 |
| 수강 중 과목 | 이수 완료로 자동 인정하지 않음. MVP에서 별도 계획 가정으로 포함할 경우 표시 |
| 목표 총학점 | 선택 숫자 + 출처(개인 졸업사정 확인 / 사용자 목표). 없으면 완료 학기 추정을 보류 |
| 개인별 미이수 필수과목 | 확인한 목록만 입력. 일반 교육과정표의 모든 과목을 필수로 취급하지 않음 |
| 관심 진로 | 정보보안 / 데이터 분석 복수 선택 가능. 미선택이면 두 진로를 탐색 대상으로 사용하며 “미정” 표시 |
| 학점 페이스 | 고정값 또는 후보 비교. 사용자 희망 상한과 학교/계획용 상한을 구분 |
| 병역 | 완료 / 예정 / 해당 없음 / 미정. 성별은 수집하지 않음 |
| 교환학생·휴학 | 계획 없음 / 포함 / 미정. “포함”은 유지해야 할 조건, “미정”은 선택 가능한 조건 |
| 우선순위 | 빠른 계획 완료 / 진로 핵심 과목 / 여유 있는 학기 / 교환 경험의 순서를 지정 |

전체 학기 배치에 필요한 최소 값은 시작 학기, 이수 현황, 계산에 포함할 중단·교환 기간이다. 목표 총학점 없이도 과목 배치는 가능하지만 완료 시점은 `null`이다. 이수 현황이 미정인 경우 이미 들은 과목을 재수강하도록 확정 배치하지 않고 추천 목록과 입력 보완 안내를 제공한다.

### 4.2 입력 오류와 미확인 상태

- 음수·비정상 숫자, 전공학점이 총학점을 초과하는 값, 종료가 시작보다 이른 기간은 입력 오류다.
- 공식 수치나 이수 현황을 모르는 것은 오류가 아닌 **정보 부족**이다.
- 성적표에서 못 찾은 항목을 버리지 않고 미인식 목록으로 보여준다. 같은 학수번호를 중복 합산하지 않는다.
- 성적표에 전체 누적학점이 확인되지 않으면 인식한 일부 과목의 합을 누적학점으로 자동 확정하지 않는다.
- 자료의 개인 적용 여부, 추가 수강 허용 여부 등은 확인 전까지 사용자 계획의 확정 근거로 쓰지 않는다.

## 5. 학기·중단·교환학생 계산

### 5.1 공통

- 화면은 엔진 결과를 표시한다. 학점, 완료 학기, 순위와 기간을 화면에서 다시 계산하지 않는다.
- 내부 날짜 구간은 `[startDate, endDate)`: 시작 포함, 종료 제외.
- 실제 학사일정이 없으면 기존의 1학기 3~6월·2학기 9~12월 구간을 **계획용 가정**으로 표시한다.
- 최대 탐색 범위는 현재 엔진과 같은 24개 미래 학기로 둔다. 초과하면 이유와 부분 결과를 제공한다.
- 확인한 필수과목을 우선 배치하고, 그다음 진로 추천 과목을 배치한다. 확인한 선수관계와 학기 제약을 지킨다.
- 권장 이수학년·권장 순서를 공식 수강 금지 조건으로 바꾸지 않는다. 엔진의 현재 처리 방식은 구현 카드에서 점검한다.
- 자료에 없는 학점은 “미배정 학점” 슬롯으로 표시하며 특정 과목·교양필수 충족으로 간주하지 않는다.

### 5.2 군 복무·휴학

- 군 복무는 입대 예정일, 전역 예정일 또는 사용자가 입력한 예상 기간, 희망 복학 학기를 구분한다.
- 휴학은 시작 학기와 복학 학기 또는 쉬는 학기 수를 받는다.
- 전역 예정일 이후 수업 시작이 가능한 학기를 계산상 복학 후보로 제시하되 학교의 복학 승인을 보장하지 않는다.
- 사용자가 더 늦은 복학을 선택하면 그 시점까지 수강 중단을 반영한다.
- 시작 시점이 미정이고 기간은 정해졌다면, 시작 학기 이후의 서로 다른 미래 시점 후보를 최대 3개 만든다.
- 기간 자체가 미정이면 기간을 추측하지 않는다. 해당 후보는 “기간 확인 필요”로 유지하고 중단 이후의 완료 시점·정밀 학기 배치는 보류한다.
- 과거에 완료한 병역·휴학은 미래 중단으로 다시 추가하지 않는다.
- 중단 구간을 합쳐 수강 불가 여부를 판단하되 이벤트별 설명은 보존한다. 서로 양립할 수 없는 군 복무와 교환 기간의 겹침은 충돌로 표시한다.

### 5.3 교환학생 권장안

- 학기 상태는 최소 `study / break / exchange`로 구분한다.
- 교환 기간에는 국내 수강 과목을 자동 배치하지 않는다.
- 예상 인정학점, 인정학기 여부, 국내 과목 대체 인정은 별도 항목이다.
- 인정학점·학기가 미정이면 `null`을 유지하고 이후 학년 진행·완료 추정을 확정하지 않는다.
- 사용자가 인정학점·학기를 **계획 가정으로 명시**한 경우에만 해당 가정을 사용한 조건부 시나리오를 계산한다. (기본 MVP 완료 후 선택 작업. MVP에서는 인정 미정 상태로 표시만 한다.)
- 가정 학점은 실제 이수학점과 분리하고, 총학점·전공학점에 중복 합산하지 않는다.
- 특정 국내 과목의 대체 인정 근거가 없으면 선수과목 이수로 처리하지 않는다.
- 실제 교환학생 선발·지원 자격·학점 인정 자동 판정은 향후 확장이다.

### 5.4 학기별 학점 상한

1. 개인이 포털에서 확인한 적용 상한이 있으면 적용 범위·확인일과 함께 우선 사용한다.
2. 없으면 S2의 학번별 기본/예정 기준을 계획용으로 사용하고 근거와 상태를 표시한다.
3. 자료 적용 범위 밖이면 학교 상한은 미확인이다. 사용자 상한만으로 시나리오를 보여주되 승인된 수강계획이라고 표현하지 않는다.
4. 학기별 배치 상한은 사용자 희망 상한과 해당 학기의 적용 가능한 상한 중 작은 값이다.
5. 다중전공·특정 교과목·재수강 등의 추가 허용학점은 개인 자격과 과목이 확인되기 전 자동 가산하지 않는다.
6. 계획 학점이 최소 기준에 못 미치면 경고한다. 임의의 과목이나 이수 완료 학점을 만들어 채우지 않는다.

## 6. 맞: 후보 생성과 순위

### 6.1 후보 생성

- **진로**는 정보보안·데이터 분석 분류이고, **트랙**은 진로·병역·휴학·교환·학점 페이스를 결합한 개인 계획이다.
- 사용자 고정값은 후보 생성에서 변경하지 않는다. “계획 없음”인 이벤트를 자동 추가하지 않는다.
- 비워 둔 시점만 미래 후보로 펼친다. 학점 페이스의 비교값은 15·18·20학점을 초기 **서비스 설정**으로 제안하되, 학교 규정이나 개인 승인값으로 표현하지 않는다.
- **MVP 탐색은 진로 최대 2개 × 병역 시점 최대 3개 × 학점 페이스 최대 3개, 총 18개 이내로 제한한다.** 휴학·교환은 MVP에서 사용자가 입력한 고정값만 반영하고 시점 후보로 펼치지 않는다. 휴학·교환 시점 펼치기(최대 162개 조합)는 기본 MVP 완료 후 선택 작업이다.
- 기간 길이는 사용자 값 또는 명시적으로 채택한 가정을 유지한다. 복무기간 후보를 임의 추가하지 않는다.
- 기존에 입력한 여러 중단 기간은 모두 유지한다. 여러 미정 이벤트를 동시에 최적화하는 기능은 후속으로 두고 미정값을 먼저 좁히도록 안내한다.
- 각 후보는 동일한 자료·설정 버전으로 엔진을 실행한다. 결과를 미리 작성한 카드로 대체하지 않는다.
- 동일 진로·이벤트·배치 결과인 후보는 중복 제거한다. 제거 기준과 대표 선택은 결정적으로 고정한다.

### 6.2 후보 상태

| 상태 | 예 | 표시·처리 |
|---|---|---|
| 계산 가능 | 필요한 입력이 있고 계획 배치가 완료됨 | 순위와 완료 추정 표시. 남아 있는 가정도 함께 표시 |
| 조건부·정보 부족 | 목표학점 미입력, 교환 인정 미정, 미래 개설 미확인 | 후보 유지. 계산할 수 없는 지표는 “확인 필요” |
| 명시적 충돌 | 잘못된 날짜, 고정된 군 복무·교환 겹침, 확인된 필수 제약 위반 | 정상 후보에서 제외하고 제외 이유 표시 |
| 탐색 한계 | 24학기 안에 배치 완료 못 함 | 부분 결과·미배정 이유 제공. 실제로 불가능하다고 단정하지 않음 |

후보가 0개면 어떤 조건이 막았는지와 사용자가 변경할 수 있는 입력을 보여준다. 1~2개면 그 수만 보여주며 3개를 맞추기 위해 가짜 후보를 추가하지 않는다.

### 6.3 공개 정렬 규칙 v1 — 권장안 채택

MVP는 서로 다른 단위에 임의 가중치를 부여한 총점 대신, **사용자 우선순위 순서의 사전식 정렬**을 쓴다. 첫 지표가 같을 때 다음 지표로 비교한다.

| 우선순위 | 비교 지표 | 좋은 방향 |
|---|---|---|
| 빠른 계획 완료 | 같은 시작 학기를 기준으로 한 예상 계획 완료 학기 인덱스 | 빠를수록 우선 |
| 진로 핵심 과목 | 진로 설정의 핵심 과목을 언제 이수하는지의 평균 미래 학기 인덱스 | 이를수록 우선 |
| 여유 있는 학기 | 수강 학기 중 최대 계획학점, 같으면 평균 계획학점 | 낮을수록 우선 |
| 교환 경험 | 입력에서 허용한 교환 경험의 포함 여부 | 포함 후보 우선. MVP에서는 교환이 고정 입력이므로 모든 후보가 같아 비교에서 자동 제외될 수 있다 |

- 핵심 과목 목록과 추천 이유는 검토한 서비스 분류 자료다. 학교 공식 진로 트랙이라고 부르지 않는다.
- 이미 이수한 핵심 과목의 시점은 0, 24학기 안에 배치 못 한 과목은 25로 계산하고 미배정 사실을 표시한다. 해당 진로의 핵심 과목 목록이 없으면 이 지표는 미확인이다.
- “여유”의 평균에서 군 복무·휴학 학기는 제외한다. 교환학점이 미정이면 해당 지표도 계산 가능 여부를 확인한다.
- 비교 대상 중 하나라도 특정 지표를 계산할 수 없으면 그 지표는 **이번 비교 전체에서 제외**하고 사유를 표시한다. 미확인을 0점이나 가장 빠른 완료로 취급하지 않는다.
- 모든 지표가 미확인이면 순위를 붙이지 않고 “비교 정보 부족” 후보 목록으로 보여준다.
- 모든 지표가 같으면 정규화된 입력으로 만든 안정적인 ID 순서로 표시하고 “평가 동률”을 안내한다.
- 순위 설명은 실제 비교 지표로 생성한다. AI가 순위·점수를 바꾸지 않는다.
- 최초 상위 3개, 더 보기에서 나머지를 제공한다. 자료·설정·입력이 같으면 순위와 이유가 같다.
- 가중 총점, 다양한 유형의 대표 후보 선별은 별도 검증 후 확장한다.

## 7. 선택·피드백·버전·확정

### 7.1 기본 기능

1. “이 트랙으로 시작”을 누르면 후보의 입력·결과를 복사하여 v1을 만든다.
2. 기본 피드백은 입대 시점 조정, 복학 학기 조정, 학점 페이스 변경, 진로 변경이다.
3. 변경 전 적용할 값과 영향받는 조건을 보여준다. 고정 조건을 바꾸려면 사용자가 해당 변경을 명시적으로 선택해야 한다.
4. 날짜 이동은 전역 예정일/예상 기간/복학 학기 중 무엇을 함께 이동하는지 미리 보여준다. 독립적으로 확정한 날짜를 몰래 이동하지 않는다.
5. 변경을 검증하고 다시 계산한 뒤에만 새 버전을 추가한다. 실패하면 이전 버전 유지와 이유 표시.
6. “맞다!”로 버전 하나를 확정한다. “다시 맞추기”는 그 버전에서 수정 화면으로 돌아간다.

### 7.2 버전 저장과 비교

- 저장: `planId, versionId, parentVersionId, createdAt, input, result, catalogVersion, engineVersion, rankingVersion, assumptions`.
- 입력·결과를 스냅샷으로 저장한다. 새 자료나 엔진을 불러와도 과거 버전을 조용히 재계산하지 않는다.
- 서로 다른 두 버전을 선택해 입력 변화, 과목 이동, 학기별 학점, 중단/교환 구간, 완료 시점 차이, 경고를 비교한다.
- 어느 한쪽 완료 시점이 없으면 그 비교값만 “비교 불가”로 표시한다.
- 저장 스키마는 v2로 올린다. 기존 v1 입력·플랜 A는 변환 가능할 때만 가져오고 실패 시 안내한다.
- MVP는 브라우저 저장만 사용한다. 저장 실패·용량 초과를 사용자에게 알린다.
- 기본 보관 한도는 최근 20개 버전으로 제안한다. 확정 버전은 보존하고, 한도에 도달하면 사용자가 오래된 버전을 정리하도록 안내한다.

### 7.3 기본 완료 이후의 피드백

- “이 과목 먼저”: 과목 우선순위 입력 계약, 확인된 선수관계·개설학기·학점 상한을 지키는 엔진 지원이 먼저 필요하다. 지원 전에는 동작하는 버튼처럼 제공하지 않는다.
- AI 자유 문장: 우선 “학기당 N학점으로 바꾸기” 한 종류만 검토한다. 버튼과 같은 검증·계산 경로를 사용한다.
- AI는 이름·성적표 원문을 받지 않으며 서버에서만 호출한다. 허용된 변경 필드·숫자 범위를 검사하고 적용 전 확인 화면을 보여준다.
- 키 없음·시간 초과·형식 오류이면 버튼형 수정으로 계속 진행한다. 규칙으로 처리한 기능을 AI라고 표시하지 않는다.

## 8. 다: 결과 화면과 자료 신뢰도

### 8.1 화면 구성

| 화면 | 필수 내용 |
|---|---|
| 아 입력 | 입력 섹션, 성적표 인식 확인, 기간·가정, 누락 항목과 영향, 후보 만들기 |
| 맞 후보 카드 | 순위 또는 동률/비교 보류, 트랙 이름, 실제 입력 기반 태그, 완료 추정, 핵심 과목, 주요 가정 |
| 후보 상세 | 학기 미니 타임라인, 평가 지표, 장점·주의점, 확인할 근거, 선택 버튼 |
| 맞 수정·비교 | 현재 조건, 지원하는 피드백, 버전 목록, 두 버전 비교, “맞다!” |
| 다 로드맵 | 연도·학기와 학년 진행 구분, 수강/중단/교환, 이수구분, 미배정 슬롯, 확인사항, PDF, 다시 맞추기 |
| 자료 출처 | 제공 자료명·쪽수·검토일·적용 범위, fixture/DB 상태, 자료 버전 |

### 8.2 준비사항

- 로드맵에 따라 교육과정·필수과목 재확인, 복학 절차 확인, 교환학점 인정 확인, 진로 핵심 과목 준비를 만든다.
- 실제 날짜가 확인된 항목만 날짜순 일정으로 표시한다.
- 날짜가 없으면 “복학 전에 확인” 등 상대적 준비 시점과 “신청 기간 미확인”을 구분한다. 임의 마감일을 만들지 않는다.
- 체크 상태를 저장하며 계획 변경으로 더 이상 관련 없는 항목은 그대로 완료된 것처럼 재사용하지 않는다.
- 자격증·다전공·선배 추천은 검토된 자료가 확보된 경우에만 선택적으로 소개한다. 기본 시연의 필수 데이터로 삼지 않는다.

### 8.3 근거와 확인 상태는 별도 표시

| 근거 종류 | 예 |
|---|---|
| 공식 문서 | 과목·규정. 제공 PDF/학교 원문과 적용 범위 표시 |
| 서비스 추천 | 진로 태그·핵심 과목·정렬 규칙 |
| 사용자 입력 | 이수 현황·목표학점·예정일 |
| 선배 추천 | 실제 작성자가 있는 검토된 팁. 표시 이름은 동의받은 정보만 사용 |
| AI 설명 | 검증된 입력·결과를 풀어쓴 설명. 사실의 원출처를 대체하지 않음 |

근거 종류와 별도로 `확인 / 예정 기준 / 사용자 가정 / 미확인` 상태를 표시한다. “공식 자료에서 가져옴”과 “이 사용자·미래 학기에 적용됨”을 같은 의미로 처리하지 않는다.

## 9. 데이터·구현 경계

- 공통 타입은 `src/contracts/**`, 순수 계산은 `src/engine/**`, 준비사항 생성은 `src/features/guidance/**`가 담당한다.
- 화면은 `getCatalog()`를 통해 자료를 받으며 DB SDK·학교 웹사이트를 직접 호출하지 않는다.
- 과목·진로 분류·기본 준비 템플릿·비교 설정은 검토한 JSON fixture로 먼저 제공할 수 있다.
- “결과 하드코딩 금지”는 입력과 무관한 후보·점수·로드맵을 미리 정해 보여주지 않는다는 뜻이다. 검토 자료·상수·명시된 알고리즘 자체를 금지하지 않는다.
- 자료와 설정은 버전을 기록한다. 자료를 DB로 옮겨도 계산 규칙을 문자열 코드로 실행하는 방식은 사용하지 않는다.
- `CATALOG_SOURCE=fixture`는 개발용 검토 자료, `supabase`는 게시본으로 명시한다. DB 실패를 fixture로 숨기지 않는다.
- 추출 자료는 학수번호·중복·학점·참조·쪽수·빈 학기를 검사하고 사람이 검토한다. 원문 해시와 수집/검토 기록을 남긴다.
- 이수학기 공란은 `null`로 유지한다. 표의 권장 순서를 공식 선수관계로 만들지 않는다.
- 신규 계약에는 교환학기, 개인 적용 정보, 학기별 상한/근거, 후보 상태, 순위 근거, 버전 스냅샷이 필요하다. 기존 타입과 API에 이미 있다고 가정하지 않는다.

## 10. 구현 범위와 완료 기준

### 10.1 기본 MVP — 이후 구현할 필수 범위

- 입력·검증과 부분 입력 처리.
- 학교 자료의 검토본, 출처·이수구분·학번별 계획 기준 표시.
- 고정 조건을 보존하는 후보 생성(진로·병역 시점·학점 페이스, 18개 이내), 공개 정렬, 최대 3개 초기 카드와 상세.
- 군 복무·휴학 기간 반영, 교환학기의 별도 상태(입력·표시·국내 과목 미배치)와 미확인/가정 처리. 교환 인정학점 가정 시나리오 계산은 선택 작업.
- 지원하는 버튼형 수정, 불변 버전 저장, 두 버전 비교, 확정·다시 수정.
- 로드맵, 준비사항 체크, 인쇄·PDF, 새로고침 후 복구.
- PC에서 전체 흐름과 오류·미확인·빈 후보·자료 실패 상태 검증.

### 10.2 기본 기능 완료 후 선택 작업

- 휴학·교환 시점 후보 펼치기(최대 162개 조합).
- 교환 인정학점·학기를 사용자가 가정으로 입력한 조건부 시나리오 계산.
- AI 자유 문장 해석 1종.
- 검토한 자격증 후보·선배 팁 소개.
- 과목 우선배치 피드백.
- Supabase 게시본 전환 및 자료 가져오기 자동화.

### 10.3 발표에서 설명할 향후 확장

- 카카오톡 알림, 예약 발송, 구독·해지·삭제, 카카오 인증, 캘린더 내보내기.
- 신청 공지 자동 수집·검토, 변경/취소 추적과 중복 발송 방지.
- 교환학생 지원 자격·실제 학점 인정 연동.
- 다전공 후보 조합·졸업요건 통합 판정.
- 다른 학과 확대, 사용자 계정·기기 간 동기화, 선배 작성·인증·신고.

### 10.4 기본 MVP 인수 시나리오

|---|---|---|

| AC-05 | 군 복무·휴학·교환 | 국내 과목 중복 배치와 학점 중복 없음, 조건부 인정 표시 |

## 11. 후속 자료 확인과 권장안 유지 조건

| 추가 확인 | 현재 처리 | 확인 후 바뀌는 부분 |
|---|---|---|
| 개인 졸업사정의 총/영역별 학점·필수 목록 | 사용자 목표와 미확인 표시 | 적용 조건이 있는 요구학점·필수과목 계산 |
| 복학 후 적용 교육과정 | 현재 자료 유지 가정과 재확인 안내 | 해당 학년·학기 자료로 재계산한 새 버전 |
| 개인 수강 상한·추가 인정 | 기본/예정 기준, 예외 가산 보류 | 확인된 범위의 학기별 상한 |
| 교환 인정학점·학기·대체 과목 | 별도 이벤트와 조건부 계획 | 확인된 인정 내역 반영 |
| 군 복무 일정·학교 복학 기준 | 사용자 입력/가정 | 확인한 일정으로 재계산 |
| 미래 개설·신청 공지 | 미확인, 공식 확인 경로 안내 | 새 자료 버전과 날짜 있는 일정 |

추가 자료가 확보되어도 기존 계획을 조용히 바꾸지 않는다. 달라지는 근거와 결과를 보여주고 사용자가 새 버전을 선택하도록 한다.
