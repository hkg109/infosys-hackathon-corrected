## 2. 근거와 개인 적용 상태

자료가 공식 문서에 적혀 있는지와 특정 사용자에게 적용되는지는 별도 상태다.

| 축 | 값 예시 | 의미 |
|---|---|---|
| 근거 종류 | 공식 문서, 서비스 추천, 사용자 입력 | 사실이나 추천이 어디에서 왔는지 |
| 문서 상태 | 확인, 예정 기준, 미확인 | 제공 원문에서 확정적으로 적힌 내용인지, 향후 적용 예정인지 |
| 개인 적용 | 확인, 조건부, 미확인 | 학번·학적·학년·학기 등을 대조해 사용자에게 적용되는지 |

예를 들어 S2 17쪽의 20학점 기준은 “공식 문서에서 확인”했지만 2025학년도 입학자까지라는 범위가 있다. 사용자의 학번과 학적을 모르면 개인 적용은 `미확인`이다. S2 17~18쪽의 18학점 기준은 공식 문서에 “조정 예정”으로 적혀 있으므로 문서 상태도 `예정 기준`이다.

## 3. S1 과목표 자료 사전

### 3.1 적용 범위와 제한

- 캠퍼스: 서울
- 학과: 정보시스템학과
- 화면 선택 탭: 2024~2027
- 원문 안내: 교육과정은 매 학기 변동될 수 있으므로 한양인포털 교육과정조회를 확인해야 한다.
- 표에 있는 개설·종료 범위는 교육과정 수록 범위다. 미래 학기 실제 개설, 시간표, 정원, 폐강을 보장하지 않는다.
- 표의 이수구분은 교육과정표 표기다. 개인 적용 이수구분과 필수 여부는 S2 16·19·20쪽의 절차로 다시 확인해야 한다.
- 표에는 공식 선수관계가 없다. 학년·학기·이수단위를 선수조건으로 변환하지 않는다.

### 3.2 필드

| 원문 열 | 후보 필드 | 형식 | 공란 처리 | 사용 시 주의 |
|---|---|---|---|---|
| 학수번호 | `code` | 문자열 | 허용하지 않음 | 자료 버전 안에서 유일해야 함 |
| 과목명 | `name` | 문자열 | 허용하지 않음 | DB-1 후보는 화면의 한국어 표기를 보존 |
| 학점 | `credits` | 양수 | 허용하지 않음 | 이론·실습 시간의 합과 항상 같다고 가정하지 않음 |
| 이론 | `lectureHours` | 0 이상 숫자 | 허용하지 않음 | 현재 `Course` 계약에는 없음 |
| 실습 | `practiceHours` | 0 이상 숫자 | 허용하지 않음 | 현재 `Course` 계약에는 없음 |
| 이수구분 | `category` | 원문 문자열 | `null` | 개인 필수 판정과 분리 |
| 이수단위 | `unit` | 숫자 | `null` | 의미를 추측해 계산 제약으로 사용하지 않음 |
| 이수학년 | `recommendedYear` | 1~4 | `null` | 권장 배치 정보이지 수강 금지 조건이 아님 |
| 이수학기 | `recommendedSemester` | 1, 2 또는 `null` | `null` | HYR0004·ITE4088은 원문 공란 |
| 개설연도/학기 | `offeringStartYear`, `offeringStartSemester` | 연도, 1·2 | `null` | 교육과정 수록 시작 표기 |
| 종료연도/학기 | `offeringEndYear`, `offeringEndSemester` | 연도, 1·2 | `null` | 해당 시점까지 실제 개설된다는 보장이 아님 |
| PDF 쪽/쪽 내 행 | `sourcePage`, `rowOnPage` | 양의 정수 | 허용하지 않음 | 원문 재검토 위치 |

현재 공통 계약은 개설 시작 학기, 종료 학기, 이론·실습, 이수단위, 원문 쪽을 모두 보존할 수 없다. BE-1에서 보존 위치를 합의하기 전에는 후보 자료를 fixture로 덮어쓰지 않는다.

### 3.3 59행 대조

검토 전 추출본은 `data/candidates/s1-infosys-curriculum-2024-2027.candidate.json`이다.

| PDF 쪽 | 원문 행 수 | 후보 행 수 | 첫 학수번호 | 마지막 학수번호 |
|---:|---:|---:|---|---|
| 1 | 5 | 5 | CUL0203 | SYH0001 |
| 2 | 11 | 11 | CUL0201 | CUL0207 |
| 3 | 14 | 14 | ITE2020 | ELE3020 |
| 4 | 13 | 13 | ACC2056 | ITE4035 |
| 5 | 11 | 11 | ITE3051 | ITE4023 |
| 6 | 5 | 5 | HYP3003 | HYP4002 |
| 합계 | 59 | 59 |  |  |

DB-2 검토에서는 다음 순서를 지킨다.

1. 후보 JSON이 파싱되고 `courses.length === 59`인지 확인한다.
2. 페이지별 `sourcePage` 개수를 위 표의 `5·11·14·13·11·5`와 대조한다.
3. `(sourcePage, rowOnPage)`가 페이지마다 1부터 끊김 없이 이어지는지 확인한다.
4. 학수번호 중복, 빈 학수번호, 0 이하 학점을 검사한다.
5. 각 페이지를 렌더링해 학수번호·과목명·학점·이수구분·학년/학기·개설/종료 표기를 행 단위로 대조한다.
6. 공란은 추측해 채우지 않고 `null`과 검토 메모를 남긴다.
7. 기존 17과목 fixture와 차이를 학수번호 기준으로 기록한다. 59개를 맞추기 위해 행을 만들거나 모든 과목을 개인 필수과목으로 취급하지 않는다.

## 5. 아직 확정할 수 없는 값

- 개인별 총·전공·교양 졸업학점과 필수과목 목록
- 개인별 적용 교육과정과 실제 이수구분
- 과목별 공식 선수관계
- 미래 학기의 실제 개설·시간표·정원·폐강 여부
- 예외를 포함한 개인별 수강 상한
- 교환학생 인정학점·학기·대체과목
- 군 복무기간과 복학 승인 조건

이 값은 `unknown` 또는 사용자에게 출처와 함께 확인받은 값으로만 다룬다.
